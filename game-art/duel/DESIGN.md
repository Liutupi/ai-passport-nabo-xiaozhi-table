# 《NABO 对决》设计文档（M0）

两台 AI Passport 工牌面对面联机的快枪手反应对决。屏幕喊“拔！”的瞬间，谁先按 OK 谁赢；抢跑直接判负。也能一台工牌单人对战 NABO 练手。

放进 **NABO 牌桌**（`ai-passport-nabo-xiaozhi-table`），作为封面上的第四张桌子“对决 · 联机”。这是本仓库第一个联机玩法，联机层（`nabo_link`）写成独立模块，以后联机大话骰、跨屏乒乓直接复用。

> 状态：M0 设计 + 浏览器原型（`prototype/index.html`）。原型是规则和协议的标准答案，改规则先改原型。

## 1. 一句话 & 按键

- **一句话**：两人对峙，NABO 屏住呼吸，“拔！”——比谁的反应时间短。
- **按键**

| 键 | 封面 / 大厅 / 结算 | 对峙中 |
|---|---|---|
| OK | 确认 | **拔枪**（按下沿生效） |
| UP / DOWN | 选择 | 无作用，不算抢跑 |
| UP 或 DOWN 长按 1 秒 | — | 暂停菜单（继续 / 认输退出） |
| UP 双击 / 长按 | 返回上一级 / 回小智（仅封面） | 屏蔽 |

对峙中 OK 是唯一的游戏键，所以暂停改用 UP/DOWN 长按，避免“按住 OK 想暂停”被判抢跑。

## 2. 结构

```
牌桌封面 → 对决封面
 ├─ 联机对战 → 大厅（找对手）→ 对局 → 整场结算
 ├─ 单人练习（对 NABO，三档难度）
 └─ 设置：局数 1 / 3 / 5（一局定胜负 / 三局两胜 / 五局三胜）、虚晃 开 / 关
```

NVS 新键（不动已有键）：`duel_bo`（1/3/5，默认 3）、`duel_fake`（默认开）、`duel_best`（个人最快反应，ms）、`duel_ai`（练习难度）。

## 3. 一局的流程

1. **准备**（1.5 s）：双方 NABO 进场摆架势，显示比分。
2. **对峙**（随机 1.0–4.0 s）：风声、心跳越来越快。屏幕上 NABO 一动不动。
3. **虚晃**（设置开启且从第 2 局起）：对峙中可能出现 0–2 次假信号：黄色“拔？”、NABO 手指一抖、风滚草滚过。**假信号从不使用反色闪屏**。按了就是抢跑。
4. **拔！**：整屏瞬间反色 + “拔！”大字 + “叮”声。从这一刻开始计反应时间。
5. **判定**（见第 4 节），双方屏幕显示两个人的反应时间和胜负演出。
6. 结果展示 2.6 s 后自动进入下一局（房主趁这段时间重新对时）。打满局数 → 整场结算：「再来一场」/「回大厅」。

### 判定规则（两台各自独立算，结果必然一致）

每台工牌对本局只上报一次自己的结果：`有效 r ms` / `抢跑` / `没按`。

| 我 | 对手 | 结果 |
|---|---|---|
| 有效 a | 有效 b | a < b 我赢；a = b 平局重来 |
| 有效 | 抢跑 / 没按 | 我赢 |
| 抢跑 | 没按 | 我输 |
| 抢跑 | 抢跑 | 平局重来（“都太急了”） |
| 没按 | 没按 | 平局重来（“都睡着了？”） |

- 拔枪信号后 2.0 s 内没按 → `没按`。
- **锁定规则**：本局结果在三种时刻锁定——自己按下；收到对手的结果；超时。锁定后立即上报，之后的按键不再计入。
  - 自己抢跑 → 立刻锁定上报 `抢跑`，对手收到后若还没按，锁定为 `没按`，于是对手赢。
  - 对手先报有效 `b`：只要本地时钟已经过了 `GO + b` 而自己还没按，就锁定为 `没按`（再按也一定比 b 慢）。按键时间以按下沿的时间戳为准，先处理时间戳更早的事件，所以“我 b−1 ms 按了但数据包先到”的情况仍然算我赢。
- 平局重来不计局数，最多连续重来 3 次后本局判平、不计分直接进入下一局（防止死循环）。

### 公平性：比的是反应时间，不是谁的数据包先到

网络延迟只影响“对手的结果多久显示出来”，不影响胜负：

- **对时**：每局开始前，房主连发 8 次 PING，客人回 PONG（带本机收到时刻）。取往返时间最短的一次算时钟偏差，误差约为最短往返的一半（ESP-NOW 通常 1–4 ms → 误差 ≤ 2 ms）。
- **同一时刻拔枪**：房主选 `go_at`（房主时钟），按偏差换算成客人时钟发过去，至少提前 800 ms，留足重传时间。客人若在 `go_at` 前不到 200 ms 才收到，回 `LATE`，房主重新安排本局。
- **拔枪信号用一条 ST7789 命令**：`INVON`（整屏反色）只是一次 SPI 命令，几微秒就完成，两台完全一样，不受整屏重画 55–180 ms 的影响。反应时间从发出 `INVON` 那一刻算起；“拔！”文字随后增量画上。
- 按键：ADC 按键 5 ms 轮询、去抖 2 拍，两台都有约 10–15 ms 的固定延迟和 ±5 ms 抖动，对双方对称。

## 4. 联机协议（ESP-NOW）

### 无线电

- ESP-NOW：C3 原生、免路由器、点对点几毫秒。Wi-Fi 驱动已经在跑，ESP-NOW 只多几 KB 内存。
- **固定信道**：进入联机大厅时暂停小智的 Wi-Fi 站点（断开并停止自动重连），关闭省电（`WIFI_PS_NONE`），切到信道 1；离开对决后恢复省电设置和自动重连。小智本来就在本地程序期间暂停，退出时本来就要重新握手，用户感知不到额外等待。
- 配网模式（SoftAP 开着）下同样用信道 1。
- 待 M4 核对：`78/esp-wifi-connect` 3.3.1 的 `WifiStation` 有没有“暂停重连”的接口；没有的话在板型里调用 `Stop()` / `Start()`，并验证退出后能自动连回、能正常对话。

### 帧格式（≤ 40 字节，远小于 ESP-NOW 的 250 字节上限）

```
magic 'N''D' | ver 1 | type | session u32 | seq u16 | ack u16 | payload ≤ 28
```

- `session`：配对时由房主随机生成，过滤附近其他对局的包。
- `ver`：协议版本，不同版本的工牌在大厅里显示为“版本不同”，不能邀请。

### 消息

| 类型 | 方式 | 内容 | 说明 |
|---|---|---|---|
| `HELLO` | 广播，每 300 ms | 名字（`NABO-` + MAC 后 2 字节）、颜色、状态（空闲 / 忙）、版本 | 大厅发现 |
| `INVITE` | 单播，可靠 | 局数、虚晃开关、session | 邀请方 = 房主，用房主的设置 |
| `ACCEPT` / `DECLINE` | 单播，可靠 | — | 收到邀请 10 s 不处理视为拒绝 |
| `PING` / `PONG` | 单播 | t1 / t1 + t2 | 对时，不重传 |
| `ROUND` | 单播，可靠 | 局号、种子、`go_at`（客人时钟） | 种子决定虚晃时刻 |
| `LATE` | 单播，可靠 | 局号 | 客人收得太晚，请房主重排 |
| `RESULT` | 单播，可靠 | 局号、尝试次数、结果类型、反应 ms | 每局每次尝试只发一次 |
| `NEXT` | 单播，可靠 | — | 整场结束后选「再来一场」；双方都选了，房主开新一场 |
| `PAUSE` / `RESUME` | 单播，可靠 | — | 一方暂停，双方都停 |
| `BEAT` | 单播，每 250 ms | — | 心跳；任何包都算活着 |
| `BYE` | 单播，发 3 次 | 原因 | 退出 / 认输 |
| `ACK` | 单播 | 被确认的 seq | 收到可靠消息立即回执 |

- **可靠消息**：带 `seq`，对方收到后立即回 `ACK`；每 60 ms 重传一次，2 s 没回执算掉线。接收方按 `seq` 去重。
- **掉线**：3 s 收不到任何包 → “对手离开了”，回大厅。
- 两人同时互相邀请：MAC 较大的一方作为房主，另一方的邀请作废。

### 大厅

- 雷达动画，列出最多 4 个附近空闲的 NABO：名字、颜色、信号格（RSSI）。按信号强弱排序，最近的排第一。
- UP / DOWN 选人，OK 邀请；对方屏幕弹出“NABO-3F2A 邀你对决 · 三局两胜”，OK 接受，UP 拒绝。
- 颜色：房主暖色（玩家 1 橙），客人冷色（玩家 2 蓝），沿用牌桌配色。

## 5. 单人练习

- 对手是 NABO 本人。三档：新手（反应 330 ± 40 ms，5% 抢跑）、老手（260 ± 30，3%）、神枪（205 ± 20，1%）。
- 规则、画面、虚晃与联机完全一样，只是对手结果由本机按种子生成。
- 刷新个人最快反应 `duel_best`；脚本测试开启测试抑制，不写最高分。

## 6. 画面（240 × 320 竖屏）

```
┌──────────────────────┐
│ ● 你 2   ◆   1 对手 ● │  比分条（双方颜色）
│                      │
│      [对手 NABO]      │  对手的 NABO 正面半身，大图 ~150 px
│      面朝着你         │  头巾颜色 = 对手颜色（调色板换色）
│                      │
│   ─── 地平线 ───      │
│   准备…  / 拔！        │  提示大字
│ 你 0.213 s  对手 0.247 │  结算时的反应时间
└──────────────────────┘
```

- 你看到的永远是**对手的 NABO**，像隔着街对峙。你输了，对面 NABO 吹枪口得意；你赢了，对面 NABO 被水枪呲一脸。
- 背景：黄昏小镇剪影，用横向纯色带（RGB565 不做细渐变，防色带）。
- 拔枪时整屏反色是硬件效果，不需要素材。

## 7. NABO 的演出（美术路线：Codex 起始图 → Grok 图生视频 → 抽帧）

造型：NABO 身份不变（脸、眼睛、镜框、发型、**白帽和帽标**、比例），换西部装：小斗篷 + 头巾 + 水枪（**水枪，不是真枪**，不吓人，输家被呲水）。头巾留出独立色块，引擎按玩家颜色换调色板。

| 动作 | 用途 | 循环 | 估计帧数 |
|---|---|---|---|
| `stance` | 对峙待机：手悬在枪套旁，眼神紧盯 | 是 | 24 |
| `twitch` | 虚晃：手指一抖又收回 | 否 | 10 |
| `draw` | 拔枪射击（对手赢时） | 否 | 12 |
| `splashed` | 被呲一脸（你赢时） | 否 | 18 |
| `smug` | 吹枪口得意（你输时） | 否 | 18 |
| `laugh` | 指着你笑（你抢跑时） | 否 | 16 |
| `sleepy` | 打哈欠（都没按） | 否 | 14 |
| `enter` | 进场摆架势 | 否 | 12 |

帽标有字，不能左右镜像；本游戏全是正面，不需要镜像。

占位：原型借用牌桌已有的 NABO 帧（idle / slam / surprise / point / trophy）。

## 8. 声音（16 kHz 现场合成，复用牌桌的合成器思路）

风声（滤波噪声循环）、心跳（越来越快的低频脉冲）、虚晃“咔”、拔枪“叮”、水枪“呲”（短噪声扫频）、抢跑蜂鸣、胜利小号三连音。全部留出扬声器余量。

## 9. 技术预算

| 项目 | 预算 | 依据 |
|---|---|---|
| 应用分区 | ≤ 45 KB 新代码（模型 + 联机 + 画面 + 声音 + 新字形） | 现剩 152,784 字节 |
| 资源分区 | ≤ 450 KB 新精灵 | 3 MB 分区现用约 2.54 MB |
| 运行内存 | 沿用牌桌（显示列表、条带、精灵缓冲）+ 联机约 2 KB（收包队列 8 × 48 B、发送重传槽 4 个） | 打开后空闲堆 ≥ 60 KB |
| 帧率 | 28–30 fps；拔枪反色 < 0.1 ms | |

**新文件（M2–M4）**

| 文件 | 职责 |
|---|---|
| `nabo_duel_model.c/.h` | 纯逻辑：大厅、对局、判定、协议状态机。输入：按键（带时间戳）、收包（带时间戳）、时钟节拍；输出：待发包、音效事件、画面状态。不依赖 ESP-NOW / 屏幕 / RTOS |
| `nabo_link.c/.h` | ESP-NOW 收发、信道切换、Wi-Fi 暂停/恢复。收包回调只做带时间戳的拷贝入队 |
| `nabo_table_scene_duel.c` | 画面 |
| `nabo_duel_sound.c` | 合成音效 |

**测试**：宿主上把两个 C 模型用模拟链路连起来（延迟、抖动、丢包、乱序、掉线），和原型录的双机轨迹逐步对拍；另外有规则用例（抢跑、同时抢跑、平局、超时、晚到的 `ROUND`、对时误差）。故意改坏判定确认测试能抓到。

## 10. 待定

1. 平局阈值：现在是相同 ms 才算平局。ADC 轮询抖动 ±5 ms，是否把差距 < 5 ms 也算平局？（会多一些重来。）也可以对局中把按键轮询提高到 1 ms。
2. 碰一碰配对：两台贴在一起（RSSI > −35 dBm）同时按 OK 直接配对，跳过大厅选人。
3. 声音拔枪模式：只听“叮”不看屏幕（I2S 有 0–40 ms 缓冲延迟，需要按采样位置补偿）。
4. 对决里加入“NABO 播报员”语音？（需要小智在线，和固定信道冲突，暂不做。）
